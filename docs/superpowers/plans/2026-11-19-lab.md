# lab.zills.io Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Lab as its own prerendered site: a live shader hero, an edge-to-edge mosaic with Grid and Index views, and a shareable page per piece.

**Architecture:** A Vite and React app with one HTML template. An SSR entry renders `/` and `/<slug>/` for every piece, and `scripts/prerender.ts` writes each one to `dist/<path>/index.html` with its own head tags. The client hydrates whichever page `location.pathname` names. The content data, shaders and shader runner are ported from `~/src/repos/jzills.github.io`. Shader stills, captured headlessly and committed, cover everything that isn't running live.

**Tech Stack:** Node 24, Vite 8, React 19, TypeScript ~6.0, Tailwind v4, Vitest 5, ESLint 10, lucide-react, with versions as in `~/src/repos/zills.io/package.json` plus `lucide-react` from the resume repo.

**Spec:** `docs/superpowers/specs/2026-11-19-lab-design.md`

## Global Constraints

- Tokens as in zills.io (bg `#09090b`, surface `#111113`, border `#27272a`, fg `#fafafa`, muted `#8b8b94`), with accent `#a78bfa`. Inter and JetBrains Mono. Dark only.
- Header: `Lab` plus a violet `.`. Footer: Z/LLS mark and `zills.io ↗` linking to `https://zills.io/`. No other cross-site links in the header.
- Slugs come from `slug(title)` (lowercase, non-alphanumerics become `-`, trimmed). Piece pages live at `/<slug>/`.
- Media is served from `/media/...` (ported from `public/lab/...`). Stills are at `/stills/<slug>.webp` and `/stills/<slug>-card.webp`.
- Everything is visible in the prerendered HTML: no inline `opacity:0` or `visibility:hidden`. Shaders show their still `<img>` until they run.
- `prefers-reduced-motion: reduce`: no shader animates, and no video autoplays.
- No framer-motion. UI motion is one CSS entrance plus hover states.

## Review Focus

1. **Many live shaders on a phone:** scrolling the mosaic on a touch device must stay smooth. Only on-screen tiles run, through the pool's concurrency cap (check in Task 4 by counting running canvases with the DevTools console snippet in that task).
2. **Hydration with a random hero:** the first client render must equal the SSR one, with the random pick applied in an effect. There must be no React hydration error in the console (check in Task 4).
3. **Back navigation and shared URLs:** `/?kind=video&view=index` must open filtered and in Index view, and going back from a piece page must restore it (test in Task 4 on `parseQuery` and `toQuery`, plus a manual check).
4. **A piece whose title changes or duplicates:** slugs must be unique, and the build must fail loudly on a collision (test in Task 1).
5. **WebGL unavailable** (old devices, blocked GPU): shaders keep showing their stills, and nothing throws (check in Task 3: rendering with `getContext` returning null leaves the `<img>`).

### Task 2: Shader stills

**Files:**
- Create: `scripts/capture-stills.html`, `scripts/capture-stills.ts`, `public/stills/*.webp`
- Test: `src/data/stills.test.ts`

**Interfaces:**
- Consumes: `pieces`, `slug`.
- Produces: `stillSrc(p: Piece): string` and `stillCard(p: Piece): string` in `src/data/pieces.ts`. For shaders these return `/stills/<slug>.webp` and `-card.webp`. For images they return `images[0].src` and `.card`; for videos `clips[0].poster` for both. For audio and music they return `undefined`.

The capture page loads one GLSL file (given by query string) into a full-canvas WebGL quad with the same uniforms as `shaderPool.ts` (`u_time = 2.0`, `u_resolution`). `capture-stills.ts` runs `vite build` for that page, then for each shader runs `chrome-headless-shell --enable-unsafe-swiftshader --window-size=1600,1000 --screenshot` (path from the `CHROME` env var, defaulting to the Playwright cache path) and converts the PNG to webp (1600 wide, plus a 600-wide card) with `ffmpeg`.

### Task 3: Media components

**Files:**
- Create: `src/components/ShaderCanvas.tsx`, `src/components/PieceMedia.tsx`
- Test: `src/components/PieceMedia.test.tsx`

**Interfaces:**
- Consumes: the ported `useShaderRunner`, plus `stillSrc` and `stillCard`.
- Produces: `ShaderCanvas(props: { piece: ShaderItem & Piece; variant?: number; size: 'card' | 'full'; className?: string })`. It renders the still `<img alt="<title> — shader">` with a `<canvas>` over it. The canvas fades in only after its first frame draws. It loads the variant's source when mounted on screen, and does nothing if WebGL is unavailable or motion is reduced. The canvas carries `data-running` while it animates.
- Produces: `PieceMedia(props: { piece: Piece; size: 'card' | 'full'; variant?: number })`, which picks the right media per kind:
  - shader: `ShaderCanvas`;
  - image: `<img>` with the card or full source, `alt` from the data;
  - video: the poster `<img>` in card size (muted play on hover with a fine pointer), `<video controls>` in full;
  - music: the cover or panel in card size, the Bandcamp iframe (`bgcol=111113`, `linkcol=a78bfa`) in full;
  - audio: the panel in card size, `<audio controls>` in full.

  - full music contains `bandcamp.com/EmbeddedPlayer` and `linkcol=a78bfa`;

### Task 4: Home page (hero, filters, Grid, Index)

**Files:**
- Create: `src/lib/query.ts`, `src/components/{Header,Footer,Hero,FilterBar,Grid,IndexView}.tsx`, `src/pages/Home.tsx`
- Test: `src/lib/query.test.ts`, `src/pages/Home.test.tsx`

**Interfaces:**
- Produces: `type View = 'grid' | 'index'`, `type KindFilter = 'all' | 'shaders' | 'video' | 'images' | 'audio'`, `parseQuery(search: string): { kind: KindFilter; view: View }` (unknown values fall back to `all` and `grid`), and `toQuery(q): string` (omits the defaults).
- `Home(props: { initialSearch: string })`: SSR passes `''`, the client passes `location.search`. Filter changes call `history.replaceState`.
- Hero: SSR renders `heroPool[0]`. An effect swaps to a random pool piece. It uses `ShaderCanvas size="full"` and pauses when off screen (the runner already does). The copy follows the spec exactly.
- Grid: CSS grid, `grid-auto-flow: dense`, 3px gap, 4 columns at ≥ 900px and 2 below, rows 230px on desktop and 170px on phones. Spans: `big` 2×2, `wide` 2×1, `tall` 1×2. Each tile is `<a href={piecePath(p)}>` with `PieceMedia size="card"` and a caption that's visible on hover or focus, or always under `(hover: none)`.
- IndexView: an `<ol>` of rows (`001`, title, kind). Desktop: a sticky preview pane shows `PieceMedia size="card"` for the hovered or focused row. Phones: a 72×54 thumbnail per row.
